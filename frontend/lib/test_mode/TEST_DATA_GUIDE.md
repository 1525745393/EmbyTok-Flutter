# 测试数据准备方案

本文档说明在测试模式下，如何准备和管理测试所需的数据，确保每个测试用例可重复、可复现。

## 1. 测试环境数据

### 1.1 Emby 服务器测试数据

| 数据类型 | 准备方式 | 用途 |
|---|---|---|
| 影片（含不同评分） | 服务器端添加 5-10 部影片，评分 5.0-9.5 | 高分标签排序验证 |
| 剧集（多季） | 添加 1 部 3 季剧集，每季 5-10 集 | 剧集切换、进度记忆 |
| 收藏影片 | 收藏 3-5 部影片 | 收藏页、心形按钮状态 |
| 收藏演员 | 收藏 2-3 个演员，每人至少 2 部作品 | 关注页、演员详情 |
| 收藏合集 | 创建 1 个合集，含 3-5 部影片 | 收藏合集展示 |
| 未看完视频 | 播放到 20%-80% 退出 | 继续观看标签 |
| 已看完视频 | 播放完一部影片 | 排除已观看开关 |

### 1.2 群晖 Audio Station 测试数据

| 数据类型 | 准备方式 |
|---|---|
| 歌手（有头像+简介） | 至少 2 个，用于验证歌手详情页 |
| 歌手（无头像） | 至少 1 个，用于验证兜底 UI |
| 专辑（多碟） | 至少 1 个双碟专辑 |
| 歌单 | 创建 2 个歌单，含不同数量歌曲 |

## 2. App 端测试数据

### 2.1 通过测试模式控制台管理

| 操作 | 路径 | 说明 |
|---|---|---|
| 导出当前配置 | 测试配置导入导出 → 导出 | 分享给其他设备复现 bug |
| 导入配置 | 测试配置导入导出 → 导入 | 从 JSON 恢复测试环境 |
| 查看存储 | 存储查看器 | 检查 SharedPreferences key-value |
| 清空特定 key | 存储查看器 → 删除 | 模拟首次安装状态 |
| Mock API | API Mock → 添加规则 | 无需服务器返回空数据/错误 |

### 2.2 常见测试场景数据准备

#### 场景 A：首次安装冷启动
1. 存储查看器删除所有 `embytok_` 前缀 key
2. 或：测试配置导入导出 → 导入空配置 JSON
3. 杀 App 重开，验证登录引导页

#### 场景 B：弱网加载
1. 网络弱网测试 → 超时模拟（2s）
2. 或：HTTP 代理设置 → 指向 Charles 限速
3. 验证 loading 态、超时提示、重试按钮

#### 场景 C：空状态
1. API Mock → 添加规则 `/Items/Latest` 返回 `[]`
2. 验证推荐页、媒体库空状态 UI

#### 场景 D：服务器错误
1. API Mock → 添加规则返回 500
2. 验证错误提示、错误重试 UI

#### 场景 E：跨账号切换
1. 导出账号 A 配置
2. 清除登录，登录账号 B
3. 导入账号 A 配置，验证环境切换不串数据

## 3. 测试数据清理

- **每次回归测试前**：通过存储查看器删除测试专用 key，或用测试配置导入导出导入已知基线配置
- **测试后**：导出当前配置作为 issue 附件，便于开发复现
- **不要在生产环境使用测试数据**：测试模式仅 debug 构建可见，release 不包含

## 4. 测试设备矩阵

| 维度 | 测试组合 |
|---|---|
| 屏幕尺寸 | 小屏（5"）/ 标准（6.1"）/ 大屏（6.7"+） |
| 刘海/打孔 | 有刘海 / 挖孔 / 无刘海 |
| 系统版本 | Android 10 / 12 / 14 |
| 网络 | WiFi / 4G / 弱网 / 离线 |
| 横竖屏 | 竖屏为主，横屏验证视频播放器 |
